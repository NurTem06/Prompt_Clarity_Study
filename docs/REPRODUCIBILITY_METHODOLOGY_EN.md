# APPS Test-Case Evaluation — Methods Addendum

For the RMT Final experiment, all 270 first-attempt generated solutions are frozen before any offline correctness measurement. For each APPS problem ID in the 135-problem pool, the original benchmark's `test` split `input_output` field is retrieved from the public `metr-evals/apps` mirror. A source-identity check compares the benchmark `problem_id` against the requested ID and either verifies the source-problem URL or the original problem statement. Failed identity checks and missing/invalid test suites are excluded, not scored as model failures.

Both Clear and Ambiguous solutions for the same task receive exactly the same available reference input-output pairs. Evaluation takes place in a network-disabled, non-root Docker container with memory/CPU/PID limits. The saved first completion is executed without modification. Programs are syntax checked and then tested in order, stopping at the first failure. The detailed record contains the number of reference cases, number actually run, number passed, first failing case, failure type, checker mode, code/prompt hashes, and test-source provenance.

For tasks with uniquely determined output, token-based reference comparison is a practical baseline. For numeric problems, tolerances are taken from the source problem statement. For recognized constructive tasks, task-specific semantic validators verify output constraints rather than one reference string. Cases without independently audited semantic validation are labelled **reference-only** and omitted from the reported validated Pass@1 denominator: reference disagreement alone cannot prove that a constructive solution is wrong. A case that errors or times out during testing has no observed success. A dataset or judge failure is distinct from a model failure.

Pass@1 is the fraction of first attempts passing **all available APPS test cases** among the evaluated tasks with a suitable checker. This does not establish performance on a private online judge's full hidden test set. Report the exact evaluated denominator and, separately, the source/audit exclusions and number of APPS test cases per problem. If the APPS source cannot be retrieved, the pipeline records an error and does not substitute examples or generated tests.

Sources: https://huggingface.co/datasets/metr-evals/apps and https://huggingface.co/docs/dataset-viewer/rows .
